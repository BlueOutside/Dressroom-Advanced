# Now Bar and clock/widget lifecycle audit - 0.11.4 alpha

Installed versionCode 80, signed with the existing key. The 0.11.2 automatic depth, source-space tracking, manual-stretch initialization and grid-transfer fixes remain.

## Findings and changes

- **Empty gap and unlock:** SystemUI's `NotificationPanelViewController.isInFaceWidgetContainer` latches the plugin's content-bounds decision on DOWN. AOD's `FaceWidgetViewModel.isInContentBounds` includes the entire Now Bar stack through `aod.di1.D(View,int,int)`. The previous dispatch rejection prevented pill dragging but left the higher-level bounds test true. The shared helper now checks visible normal-content bounds for collapsed stacks, using native touch slop; expanded/settings/expanding or unmeasured stacks defer to Samsung. Other clock/widget/notification hit tests are untouched. The user confirmed gap swipe-to-unlock and direct pill dragging in 0.11.3.
- **Retained charging percentage:** `ChargerNowBarView.onAttachedToWindow` rebuilds the text and progress animation from `currentBatteryLevel`. Previously only the TextView was updated, leaving this field stale. Held cards now refresh the field, localized text and native LTR/RTL fill translation from the current battery broadcast. Reattach refreshes before native setup and settles a held card after Samsung's posted entry animation begins.
- **Charging animator type:** this SystemUI uses `androidx.core.animation.AnimatorSet`, so the old `instanceof android.animation.Animator` cancellation never ran. Cancellation now uses the actual backport contract, preserving top-level dismiss listeners without invoking them. Unknown battery readings are rejected, percentages respect scale and clamp to 100.
- **Charging text after card cycling:** the user reported missing text after the 0.11.3 animation correction. Samsung starts the inner battery container at alpha 0, with entry scales/offsets. 0.11.4 finishes those properties on the battery text container/icon/shadow after cancellation. The outer card's alpha, translation and swipe animations remain native. Awaiting user confirmation across card cycling.
- **Clock effects on time changes:** `AbsClockView.g(gi1)` deliberately calls `aod.tx0.h(int,ImageView)`, which starts a 1000 ms background/text-alpha fade, then calls `setClockTextBlur` to rebuild paths. For a clock with module depth or forced blur, the redundant tick fade is skipped; path regeneration, initial blur entry and native doze behavior remain. Fullscreen media retains its own contrast/depth lifecycle. The user confirmed reduced clock effect flashing in 0.11.3; this is not a claim that all Samsung transition effects have been removed.
- **Released widget ownership:** native `ComplicationWidgetPluginController.release()` removes children, nulls its container and unregisters observers. Our window-level media cover lookup previously remained active for a released widget root after unregistering it, potentially retaining clipping/watchers on replacement. Cover lookup now requires a registered widget ancestor, so release cleanup can restore its render-node and blur state. Replacement registered roots still see the current window cover. This is a code/probe finding, not a user-reproduced visual defect.
- **Blue rim:** resolved by the user's discovery that it is present in the source wallpaper. No further mask-color workaround is needed for that report.

## Validation and limits

- Signed APK build and v3 verification pass. SystemUI startup rendering guard passes after reloading SystemUI and AOD for both builds.
- 91 JVM checks pass, including 14 new charging percent/direction/backport cancellation checks. Cancellation tests preserve listeners even on failure.
- Android `NowBarPipelineProbe`: 16 checks on the final APK, covering pill/gap bounds, expanded/settings/transition deferral, unmeasured/invisible views, registered/released/replacement widget owners, inner charging text/icon restoration, and preservation of outer card transforms.
- 0.11.3 also passes the existing 20 Android depth contracts, 16 Region checks and 7 Samsung clipping/blur groups; 0.11.4 changes only charging entry visuals/version labels after that run.
- The first standalone view probe lacked Android's ApplicationSharedMemory initialization and exited before its assertions. The test harness was initialized correctly and then passed. This was not a SystemUI process crash. Windows memory pressure was handled by reducing test JVM memory; no user apps were terminated.
- Actual long-running charging progression, repeated card cycling, all clock styles, foldables/tablets and other firmware builds are not fully verified. The gap/clock behavior is user-confirmed; final charging-card cycling needs feedback.
